# Запуск і демонстрація двох порталів

Виконуйте з кореня репозиторію. Використовується початкова база `internet_pharmacy`; схему й каталог не потрібно скидати чи копіювати.

## Звичайний запуск

```bash
docker compose -f compose.yaml -f compose.backend.yaml up --build -d
node apps/start-portals.mjs
```

Якщо Docker вимагає прав адміністратора ОС, виконайте першу команду через `sudo`. `Ctrl+C` у терміналі Node зупиняє обидва портали. Backend і Worker залишаються працювати.

Незалежний запуск у двох терміналах:

```bash
node apps/customer-web/server.mjs
node apps/management-web/server.mjs
```

- Магазин: <http://localhost:4173/#home>.
- Службовий вхід: <http://localhost:4174/#login>.
- Django API: <http://localhost:8000/api/docs/>.

`API_ORIGIN` задає спільний Backend, `FRONTEND_PORT` — порт конкретного процесу. Не задавайте однаковий `FRONTEND_PORT` при запуску обох через `start-portals.mjs`. Для сторінок і сесій використовуйте послідовно localhost або 127.0.0.1.

Альтернативний запуск усіх компонентів у Compose (попередньо зупиніть локальні Node-процеси):

```bash
docker compose -f compose.yaml -f compose.backend.yaml -f compose.portals.yaml up --build -d
# Незалежна зупинка одного порталу:
docker compose -f compose.yaml -f compose.backend.yaml -f compose.portals.yaml stop customer-web
# Відновлення:
docker compose -f compose.yaml -f compose.backend.yaml -f compose.portals.yaml up -d customer-web
```

## Початковий адміністратор

Під час запуску оновленого Backend команда `bootstrap_admin` створює акаунт лише за відсутності будь-якого ADMIN:

- Логін: **admin**
- Пароль: **admin**.

Якщо початковий адміністратор уже був створений зі старим паролем, оновіть його явною командою:

```bash
docker compose -f compose.yaml -f compose.backend.yaml exec backend python manage.py set_coursework_admin_password
```

Для створення облікового запису, якщо він відсутній (без скидання пароля), виконайте:

```bash
docker compose -f compose.yaml -f compose.backend.yaml exec backend python manage.py bootstrap_admin
```

Якщо адміністратор уже існує, команда не створює другого, не скидає пароль і не змінює роль. Конфлікт із зайнятим логіном `admin` повідомляється окремо.

## Як створити працівника

1. Увійдіть як admin на порту 4174.
2. На вкладці **Користувачі** відкрийте **Новий запис**, введіть логін, email, роль **Працівник (STAFF)** і пароль не коротший за 4 символи.
3. Запам’ятайте ID створеного працівника та ID потрібної аптеки (ID показано в таблицях; користуйтеся пагінацією).
4. Відкрийте **Призначення персоналу → Новий запис**, вкажіть ці ID.
5. Вийдіть і увійдіть працівником. Він побачить робоче місце призначеної аптеки.

Роль ADMIN не означає кваліфікацію фармацевта. Перевірка рецептів потребує STAFF, активного призначення та ID у конфігурації `PHARMACIST_IDS` Backend.

## Наскрізний сценарій

1. На 4173 зареєструйте навчального покупця, відкрийте товар і виберіть аптеку з доступними залишками.
2. Додайте товар у кошик, виберіть аптеку й спосіб оплати **CARD**. У кошику введіть лише вигадані реквізити `DEMO USER`, `0000 0000 0000 0000`, `12/30`, `000`, оберіть сценарій і натисніть оформлення. Перевірте серверний розрахунок, потім натисніть **Підтвердити замовлення й оплатити**. Реквізити очищаються до запитів і ніколи не передаються API; Worker обробить тільки сценарій через outbox. Результат з’явиться в історії замовлень. Реальних карток і грошових переказів немає.
   Для демонстрації трьох результатів використовуйте три окремі тестові замовлення: кожне замовлення має лише одну спробу симуляції. В історії можна окремо відкрити **Оплатити** для раніше оформленого неоплаченого замовлення.
4. На 4174 увійдіть призначеним працівником. Для самовивозу переведіть замовлення через PROCESSING → READY_FOR_PICKUP → COMPLETED.
5. Оновіть історію покупця: стан повинен відповідати змінам працівника.
6. Увійдіть адміністратором у службовий портал і перевірте статистику та аудит.

У кабінеті покупця можна обрати стандартну, соціальну або Premium програму лояльності. Для соціальної введіть 6 цифр документа. Premium активується на 30 днів за 30 грн у симуляції; реального списання чи автоматичного продовження немає.

Для повторення технічної перевірки використовуйте `docs/verification/portal-split/verify_live.py`. Він створює лише позначені записи `portal.qa.*`, `PORTAL-QA-*`, зберігає результати й залишає виконане навчальне замовлення. Повторний запуск створює нове замовлення, тому не запускайте його без потреби. Пароль його синтетичних акаунтів: `Portal-QA-2026-Only`.

## Діагностика

- 4174 не відкривається: запустіть `node apps/management-web/server.mjs`; перевірте, чи порт не зайнятий.
- API недоступне: `curl --fail http://127.0.0.1:8000/api/health/`, потім логи Backend.
- 403 під час входу: перевірте портал і роль; покупець входить на 4173, STAFF/ADMIN — на 4174.
- Працівник не бачить аптек: перевірте активність користувача, аптеки та призначення.
- Старий інтерфейс: оновіть сторінку; перезапустіть Node після зміни `server.mjs`.
- JWT закінчився: увійдіть знову. Стандартний термін — 15 хвилин; refresh endpoint відсутній.
